## 4. 数据组织方式

所有原始人脸图像仅保存在本地目录：

`local_face_data/`

当前目录结构：

```text
local_face_data/
└── person_01/
```

后续增加其他授权对象后，可扩展为：

```text
local_face_data/
├── person_01/
├── person_02/
└── person_03/
```

每个对象的图像只保存在对应目录中。

例如：

```text
local_face_data/
└── person_01/
    ├── 001.jpg
    ├── 002.jpg
    ├── 003.jpg
    ├── 004.jpg
    └── ...
```

文件名仅使用编号，不在文件名中直接保存真实姓名、学号等身份信息。

---

## 5. 样本采集要求

当前计划对 `person_01` 采集不少于10张有效人脸图像。

为了增加样本差异，采集时可包含：

- 正面；
- 轻微左转；
- 轻微右转；
- 轻微抬头；
- 轻微低头；
- 不同正常表情；
- 不同室内光照；
- 不同距离下的正常人脸画面。

采集过程中应避免：

- 严重模糊；
- 过度曝光；
- 人脸区域过暗；
- 人脸被大面积遮挡；
- 图像中没有完整有效人脸；
- 人脸尺寸过小；
- 明显不适合后续检测和识别的样本。

不满足要求的图像不进入正式样本集。

## 6. 授权原则

人脸数据属于具有较强个人识别属性的信息。

本项目遵循“先授权、后采集”的原则。

在采集其他人员人脸图像之前，必须提前向被采集对象说明：

1. 图像仅用于《智能会议室管理系统 III》课程项目；
2. 图像会用于人脸识别训练和测试；
3. 原始人脸图像不会上传到公开Git仓库；
4. 报告和课堂演示中的人脸信息按照要求脱敏；
5. 数据不会用于课程之外的其他用途；
6. 课程结束后按照教师要求保存或删除。

只有在本人明确知晓并同意后，才能进行采集。

## 9. 脱敏方式

为了降低人脸数据和真实身份直接关联的风险，本项目采用以下脱敏措施。

### 9.1 使用对象编号

项目代码、文档和目录中统一使用：

```text
person_01
person_02
person_03
```

不直接使用真实姓名作为训练目录名、代码标签或公开文档中的身份名称。

### 9.2 原始图像不进入公开仓库

所有原始人脸图像保存在：

`local_face_data/`

该目录仅用于本地开发与测试。

### 9.3 Git忽略

项目根目录 `.gitignore` 已加入：

```gitignore
local_face_data/
```

因此原始人脸样本不参与Git提交。

### 9.4 报告与演示脱敏

如课程报告、答辩材料或课堂演示中需要出现人脸图像，应按照教师要求进行脱敏处理。

公开展示时不同时暴露真实姓名、学号等身份信息。

## 10. Git仓库中允许保存的内容

公开Git仓库中可以保存：

```text
face_recognition/
docs/face/
results/face/
```

例如：

- 人脸识别源代码；
- 人脸识别流程图；
- 算法说明；
- 数据组织说明；
- 授权与脱敏记录；
- 不含可识别个人身份信息的统计结果；
- 经脱敏处理后允许展示的结果材料。

公开Git仓库中不保存：

- 原始人脸照片；
- 未脱敏的人脸样本；
- 将真实姓名与人脸图像直接对应的文件；
- 未经授权的任何人员人脸数据。
